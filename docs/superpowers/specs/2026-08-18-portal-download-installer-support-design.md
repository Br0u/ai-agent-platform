# 官网 1.0 入口调整与下载中心安装包支持设计

**日期：** 2026-08-18  
**状态：** 已确认  
**范围：** 官网申请体验入口、首页与产品文案、下载中心、后台下载资源管理、公开文件下载

## 1. 目标

本次调整完成两类工作：

1. 官网 1.0 暂不展示“申请体验”入口，但保留 `/trial` 页面和现有功能，后续开放时可以恢复入口。
2. 恢复下载中心“码里奥桌面客户端”区块，并把现有 PDF-only 下载资源管理扩展为同时支持 PDF、Windows 安装包和 macOS 安装包。

本次不做视觉重设计，不调整现有页面布局、颜色、字体、动画、导航结构或 Agent/聊天能力。

## 2. 已确认的产品规则

### 2.1 官网入口与文案

- 官网公开页面不再渲染“申请体验”入口；不得只用 CSS 隐藏。
- `/trial` 路由、页面和业务能力保留。
- 五个中心 CTA 文案由“欢迎与华鲲团队沟通并申请试用。”改为“欢迎与华鲲团队沟通并联系我们申请试用。”：
  - 模型中心
  - 智能体中心
  - 行业应用中心
  - 技能中心
  - 权限中心
- 下载中心 CTA 文案改为“从产品认知到联系我们申请体验”。
- 首页首屏在“查看解决方案”右侧显示“联系我们”，进入 `/contact?topic=官网咨询`。
- 原需求中的“产品模块各中心/子页首屏按钮颜色加深”取消；本次不修改样式。

### 2.2 下载中心首屏与客户端区块

- 下载中心首屏移除“了解产品”按钮；因“申请体验”入口也不展示，整个空按钮容器一并移除。
- 获取资源路径第四步改为：
  - 标题：`联系我们`
  - 描述：`联系华鲲团队获取方案与产品支持`
  - 跳转：`/contact?topic=下载与资料咨询`
- 恢复“码里奥桌面客户端”区块。
- 客户端区块显示统一版本号、Windows 与 macOS 两个平台状态、各自文件大小和下载操作。
- 安装体验路径显示：`下载安装包 → 安装部署 → 进入使用`。
- 不恢复旧的下载确认弹窗；有资源时直接下载。
- 已发布版本缺少其中一个平台时，该平台显示“暂无资源”，不渲染可点击下载入口。
- 两个平台都没有文件的资源不能发布，也不进入公开目录，因此前台不显示空的客户端区块。

### 2.3 客户端文件规则

- Windows 允许 `.exe`、`.msi`，以及作为 Windows 分发包的 `.zip`。
- macOS 允许 `.dmg`、`.pkg`，以及作为 macOS 分发包的 `.zip`。
- 每个平台在一个资源版本中最多保存一个当前安装包。
- Windows 和 macOS 共用一个版本号。
- 任意一个平台安装包存在即可发布；两个平台都没有文件时不可发布。
- 单个安装包最大 1 GiB；PDF 继续保持 200 MiB。
- 每个文件记录原文件名、扩展名、规范化媒体类型、字节数和 SHA-256。

## 3. 方案选择

采用“资源修订 + 通用附件”方案，复用现有下载资源的草稿、发布、下线、审计、并发控制、持久化文件卷和公开下载接口。

未采用：

- 在修订表直接增加 Windows/macOS 两组字段：短期字段较少，但会把通用下载资源模型绑定到码里奥产品。
- 新建独立客户端发布后台：会重复实现资源身份、草稿、发布、审计、文件清理和下载响应。
- 允许后台上传任意文件：扩大恶意文件和错误分发风险，且没有业务需求依据。

## 4. 数据模型

### 4.1 资源修订

`download_resource_revisions` 继续保存公开展示与发布状态相关的元数据，并新增：

- `kind`：`document | software`
- `release_version`：软件资源必填，文档资源为空

权限规则按资源类型区分：

- 文档继续使用现有三种组合：公开预览/公开下载、公开预览/联系下载、联系获取。
- 软件不提供站内预览，`preview_policy` 为空且 `download_policy` 固定为 `public`。
- 数据库检查约束要求：`document` 的 `release_version` 为空且 `preview_policy` 非空；`software` 的非空版本号符合 `^[A-Za-z0-9][A-Za-z0-9._+-]{0,39}$`，且 `preview_policy` 为空、`download_policy='public'`。

### 4.2 通用附件

新增 `download_resource_artifacts`，一行表示一个修订中的一个可交付附件：

- `id`
- `revision_id`
- `revision_kind`：冗余保存 `document | software`，用于数据库复合外键与槽位约束
- `slot`：`document | windows | macos`
- `object_key`
- `original_filename`
- `extension`
- `media_type`
- `byte_size`
- `sha256`
- `page_count`：仅 PDF 使用
- `cover_object_key`：仅 PDF 使用
- 创建时间

`revision_id + slot` 唯一，保证同一修订中每个平台至多一个文件。附件通过 `(revision_id, revision_kind)` 复合外键引用修订表的 `(id, kind)`，数据库检查约束只允许 `document + document` 或 `software + windows/macos`，从而阻止文档修订持有安装包、软件修订持有 PDF。

约束规则：

- `document` 只接受 PDF，必须同时具有页数与 WebP 封面。
- `windows` 只接受已确认的 Windows 扩展名，不得具有 PDF 页数或封面。
- `macos` 只接受已确认的 macOS 扩展名，不得具有 PDF 页数或封面。
- `document` 修订发布时必须有完整 PDF 附件。
- `software` 修订发布时必须至少有一个 `windows` 或 `macos` 附件。

### 4.3 迁移

- 将现有修订中的 PDF、封面、页数、大小和 SHA-256 迁移为 `document` 附件；现有数据库没有原上传文件名，因此迁移时确定性使用 `{resource.key}.pdf`，扩展名写 `.pdf`，媒体类型写 `application/pdf`。
- 将现有文档修订标记为 `document`。
- 保留既有 `mdd2-client` 资源身份，管理员为其创建软件草稿并上传安装包。
- 本次采用维护窗口切换：先停止旧 Web/Nginx 写流量，再执行一次事务性数据库迁移与数据核验，随后部署只读取新表的新代码并恢复流量。旧代码不得在删除 PDF 专用字段后继续运行。
- 数据迁移与新代码切换完成后直接删除废弃的 PDF 专用字段，不保留兼容读取路径；迁移失败则整笔事务回滚并保持旧版本停机状态，不能启动新代码。

## 5. 上传、存储与发布

### 5.1 上传

后台上传路由显式包含附件槽位，不能由文件名推断平台。服务端按槽位执行：

1. 验证管理员身份、`admin:downloads` 权限、可信同源请求和 `If-Match` 行版本。
2. 流式解析一个文件，不把完整安装包载入 JavaScript 内存。
3. PDF 按 200 MiB 限制；安装包按 1 GiB 限制。
4. 清理原文件名，检查槽位与扩展名组合。
5. 按以下固定规则检查文件特征，不能只信任浏览器提供的 MIME 或扩展名：
   - `.pdf`：开头 `%PDF-`，媒体类型 `application/pdf`
   - `.exe`：开头 `MZ`，媒体类型 `application/vnd.microsoft.portable-executable`
   - `.msi`：开头为 Compound File Binary 魔数 `D0 CF 11 E0 A1 B1 1A E1`，媒体类型 `application/x-msi`
   - `.zip`：开头为 `PK\x03\x04`、`PK\x05\x06` 或 `PK\x07\x08`，媒体类型 `application/zip`
   - `.dmg`：最后 512 字节的 UDIF trailer 以 `koly` 开头，媒体类型 `application/x-apple-diskimage`
   - `.pkg`：只接受平面 XAR 安装包，开头为 `xar!`，媒体类型 `application/vnd.apple.installer+xml`
6. 流式计算 SHA-256，写入临时文件。
7. PDF 继续生成首页 WebP 封面并提取页数；安装包不生成封面、不执行、不解压。
8. 验证完成后先把暂存文件原子移动到服务端生成的最终对象键，再开启数据库事务创建附件和新草稿修订、切换草稿指针并写审计；数据库事务失败时删除刚提交但尚未被任何指针引用的对象。线上发布指针只在单独的显式发布事务中切换。

`.zip` 只验证为 ZIP 容器并作为附件原样保存，服务器不解压，因此不引入 ZIP 炸弹解压面；平台归属由管理员选择的槽位决定。

相同 SHA-256 的重复上传被当作普通替换接受，不做跨槽位或跨修订去重；发布和引用清理仍按对象键处理，避免引入内容寻址与共享生命周期。

### 5.2 上传基础设施

- Nginx 安装包上传路由调整为新的带槽位路径，并设置 `client_max_body_size 1025m`、`proxy_request_buffering off`、`proxy_buffering off`。
- 该路由显式设置一小时的 `client_body_timeout`、`proxy_send_timeout` 和 `proxy_read_timeout`；PDF 和安装包仍由应用层分别执行 200 MiB/1 GiB 的准确文件部分限制。
- Next.js Route Handler 直接读取 Web `Request` 流，不经过 Server Action body 上限；应用不得调用 `request.formData()` 或缓冲完整文件。
- 上传前不预留完整 1 GiB 空间；暂存写入遇到 `ENOSPC` 时终止流、清理已写暂存文件并返回 `507 insufficient_storage`。部署与运行手册要求下载资源卷至少保留“最大安装包 + 当前线上文件 + 发布替换余量”，监控磁盘使用率属于部署运维而非本功能新建监控系统。

### 5.3 文件存储

- 继续使用现有下载资源持久化文件卷。
- 对象路径只由资源 UUID、修订 UUID、附件槽位和服务端确认的扩展名生成。
- 用户文件名只作为下载显示名，不参与文件系统路径拼接。
- 文件卷备份和数据库备份继续要求同一时间点恢复。

### 5.4 草稿与发布

- 软件草稿第一次上传任意一个平台文件后进入“待发布”。
- 另一个平台未上传不阻止发布，后台明确显示该平台“暂无资源”。
- 已发布资源编辑时复制元数据并复用现有附件引用，不复制大文件。
- 替换某个平台安装包只改变草稿中的对应附件；线上旧版本继续提供下载。
- 显式发布后，草稿整体成为新的公开版本。
- 只有确认旧附件不再被发布修订或草稿引用时才能删除物理文件。
- 两个平台文件全部移除后，软件草稿不可发布。

## 6. 后台界面

`/admin/downloads` 继续使用现有列表 + 详情编辑布局。

文档资源保持现有体验：

- 上传/替换 PDF
- PDF 封面、页数、大小与草稿预览
- 预览和下载权限

软件资源改为：

- 版本号输入
- Windows 上传槽位
- macOS 上传槽位
- 每个槽位独立显示原文件名、大小、SHA-256、上传、替换和移除操作
- 不显示 PDF 封面、页数、草稿预览和预览权限
- 下载权限固定公开，不显示无实际选择的权限控件
- 上传期间锁定会造成版本冲突的资源切换和发布操作，并允许取消上传

状态仍沿用现有资源状态名称；软件资源只要存在一个完整附件即可显示“待发布”。

## 7. 公开下载中心

### 7.1 文档卡片

现有 PDF 卡片、封面、预览、联系获取和下载行为保持不变。

### 7.2 码里奥桌面客户端

`software` 栏目对 `mdd2-client` 使用恢复后的客户端区块，而不是 PDF 图文卡：

- 名称、简介、统一版本号
- Windows 支持说明、文件大小与下载状态
- macOS 支持说明、文件大小与下载状态
- 可用平台显示直接下载链接
- 缺失平台显示“暂无资源”
- 安装体验路径：`下载安装包 → 安装部署 → 进入使用`
- 两个平台都没有文件时资源不公开，整个客户端区块不显示

公开 DTO 返回各平台可公开下载附件的文件名、大小和下载 URL，不暴露内部对象键或 SHA-256。

### 7.3 下载响应

- 继续支持 GET、HEAD 和单段 HTTP Range。
- `Content-Disposition` 始终为 `attachment`，文件名同时提供安全 ASCII fallback 与 UTF-8 filename。
- `Content-Type` 使用服务端按已验证文件类型映射的固定值。
- 返回 `X-Content-Type-Options: nosniff` 和 `Cache-Control: no-store`。
- 下载接口每次重新检查当前发布修订、固定公开下载权限、附件槽位、文件存在性与实际字节数。
- 不存在的平台、未发布版本或失效文件统一返回 404，避免暴露内部状态。

## 8. 申请体验入口隐藏

增加一个公开入口可见性策略，公开页面在渲染 CTA 前过滤 `/trial`：

- 桌面 Header
- 移动导航
- Footer
- 首页
- 产品中心及子页
- 解决方案
- 下载中心及其他公开 CTA

该策略只影响公开入口渲染，不修改路由注册、`/trial` 页面、后台路由表或 Agent 协议。测试必须确认页面中不存在可访问的“申请体验”链接，同时直接访问 `/trial` 仍能正常渲染。

## 9. 错误处理与安全

- 不支持的槽位、扩展名或文件特征：`422 invalid_file`。
- 文件超过对应上限：`413 file_too_large`。
- 持久化卷空间不足：`507 insufficient_storage`。
- 非法 multipart：`400 invalid_multipart`。
- 身份、权限、同源、并发版本冲突继续沿用现有状态码和错误合同。
- 上传、派生或数据库事务失败时，不得改变线上发布指针。
- 取消上传必须终止读取并清理暂存文件。
- 公开错误不返回文件路径、对象键、解析器输出或异常详情。
- 安装包由有权限的后台人员上传；系统提供格式边界与完整性记录，不声称验证软件业务安全或代码签名真实性。

## 10. 验收

### 10.1 自动检查

- 数据库迁移：现有 PDF 数据完整迁移，旧字段删除，附件约束生效。
- 上传解析：PDF、Windows、macOS 合法格式；错误槽位、伪扩展名、空文件、重复文件正常替换、大小上限和磁盘空间不足。
- 生命周期：仅 Windows 发布、仅 macOS 发布、双平台发布、零附件拒绝发布、替换失败保留旧版本、引用安全清理。
- 后台：文档与软件编辑器分支、版本号、两个附件槽位、上传/替换/移除、缺失状态和发布门禁。
- 公开 DTO 与下载：平台隔离、权限校验、文件名、媒体类型、HEAD、Range、404 边界。
- 官网 CTA：所有公开页面不渲染“申请体验”，`/trial` 直接访问仍可用。
- 文案：首页主题、五个中心、下载 CTA、第四步骤和安装体验路径精确匹配。

### 10.2 浏览器验收

- 桌面和移动导航没有“申请体验”。
- 首页“联系我们”进入联系页并显示“官网咨询”。
- 下载中心首屏无空按钮区域，第四步正确进入联系页。
- 码里奥客户端区块分别覆盖：仅 Windows、仅 macOS、双平台；两个平台都缺失时资源不进入公开目录且区块不显示。
- 可用平台触发真实附件下载；缺失平台不可点击。
- PDF 预览、PDF 下载和联系获取行为没有回归。
- Agent 入口、聊天浮层和 `/assistant` 不发生变化。

## 11. 不做事项

- Linux 安装包
- 一个平台注册多个并行安装包
- 任意文件类型上传
- 安装包在线预览
- 服务器解压、执行、病毒扫描或代码签名认证
- 安装包版本历史与回滚页面
- 对象存储迁移或 CDN
- 客户账号下载权限
- 产品页面视觉样式调整
