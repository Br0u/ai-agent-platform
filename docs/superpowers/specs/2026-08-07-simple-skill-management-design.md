# 简化 Skill 管理设计

日期：2026-08-07

## 目标

为单一助手“码多多”提供一个简单、可理解且安全的 Skill 管理闭环。平台管理员只需要理解两个概念：

- Skill 是否存在于 Skill 库。
- Skill 当前是否已启用。

系统不向管理员暴露审核流、版本管理、候选集合、激活编号或 Registry/Agent 对账等内部机制。

## 已确认的产品边界

- 只有平台管理员可以管理 Skill。
- 全平台共用“码多多”的同一套已启用 Skill。
- 仅支持 ZIP 上传，不支持 GitHub、GitCode 或其他仓库导入。
- 不支持组织级或用户级 Skill 配置。
- 不引入多 Agent。
- 暂不扩展长对话上下文管理。

## Skill 状态

产品层只存在两种状态：

- `未启用`：Skill 已进入 Skill 库，但 Agent 不加载。
- `已启用`：Skill 已进入 Skill 库，并由 Agent 加载。

启用状态必须根据 Agent 当前实际加载的 Skill 集合计算，不能再单独维护一份可能漂移的布尔状态。

## 管理界面

页面标题为“Skill 库”，包含一个“上传 Skill”按钮和 Skill 列表。

每个 Skill 只显示一行：

- 名称
- 简介
- 上传时间
- `已启用`或`未启用`标识
- 与当前状态匹配的操作

未启用 Skill 提供：

- 启用
- 删除

已启用 Skill 提供：

- 停用
- 删除

页面不显示：

- revision 或版本编号
- 候选集合
- Registry Active、Agent Loaded、Previous
- Activation Version、Capability、Failure Code
- 创建候选、激活候选、丢弃候选或手动回滚

正常运行时只显示简短的“运行正常”。发生故障时显示用户可理解的错误信息，并允许查看必要的诊断详情。

## 上传

### 新 Skill

1. 管理员选择 ZIP 文件。
2. 服务端完成归档格式校验、安全扫描、文件限制和依赖检查。
3. 校验成功后，Skill 进入 Skill 库，初始状态为`未启用`。
4. 上传不会自动启用 Skill。

### 同名 Skill

Skill 的规范化标识由包内 manifest 的 Skill 名称确定。

1. 首次上传返回同名冲突，不修改任何数据。
2. 前端弹窗提示：“已存在同名 Skill，是否替换？”
3. 管理员确认后，前端携带目标 Skill 标识和当前内容摘要重新提交，避免并发覆盖。
4. 未启用 Skill 替换成功后仍保持未启用。
5. 已启用 Skill 只有在新内容通过校验并由 Agent 成功加载后才完成替换。
6. 替换失败或结果无法确认时，原 Skill 内容及启用状态保持不变。

产品不提供历史版本查询、版本选择或版本回滚。实现可以在切换期间暂存新旧制品；操作完成后，产品只认当前 Skill，旧制品仅作为不可访问的审计记录保留。

## 启用与停用

### 启用

1. 管理员点击未启用 Skill 的“启用”。
2. 服务端基于当前实际加载集合增加该 Skill。
3. Agent 加载成功后返回成功。
4. 页面显示`已启用`。

### 停用

1. 管理员点击已启用 Skill 的“停用”。
2. 服务端基于当前实际加载集合移除该 Skill。
3. Agent 确认不再加载后返回成功。
4. Skill 继续保留在库中，页面显示`未启用`。

启用和停用失败时必须保留操作前的运行状态。

## 删除

所有删除操作都需要二次确认。

### 删除未启用 Skill

服务端立即将 Skill 从可用库中移除。该 Skill 后续不能启用或访问；底层记录和制品仅作为不可访问的审计记录保留。

### 删除已启用 Skill

1. 服务端先从 Agent 当前加载集合中移除 Skill。
2. 确认 Agent 不再加载后，将 Skill 从可用库中移除。
3. 如果停用失败或结果无法确认，不执行删除，Skill 保持原状态。

API 返回成功时，必须同时满足“Agent 不再加载”和“Skill 已从库中删除”，不能出现界面已删除但 Agent 仍在使用的状态。

删除后的 Skill 名称可以重新使用。再次上传同名 ZIP 时创建全新的 Skill，初始状态为`未启用`；已删除记录不参与名称冲突判断，也不能被恢复。

## 后端边界

Skill Registry 继续负责：

- ZIP 规范化和制品存储
- 自动安全扫描
- Skill 元数据
- 当前 Skill 内容

Agent 运行时继续负责：

- 当前实际加载集合
- 加载与卸载
- 切换结果

Web BFF 负责把管理员操作编排成单一产品动作：

- 上传
- 替换
- 启用
- 停用
- 删除

现有候选到激活的安全机制可以作为内部事务复用，但候选不再是产品资源，不提供候选管理页面或公开管理接口。一次产品操作创建的临时运行状态应当在成功、失败或对账完成后进入终态，不能要求管理员继续处理。

## 接口语义

- `GET Skill 库`：每个 Skill 只返回当前内容和实际启用状态。
- `POST 上传`：创建新 Skill；同名时返回稳定冲突代码。
- `POST 确认替换`：校验并替换同名 Skill。
- `POST 启用`：加载指定 Skill。
- `POST 停用`：卸载指定 Skill但保留库存。
- `DELETE Skill`：未启用时直接删除；已启用时先停用再删除。

具体 URL 沿用项目现有 `/api/v1/admin/assistant/skills` 命名空间。客户端不能自行拼接多步操作来宣称成功，最终状态由服务端确认。

## 并发与失败处理

- 操作期间只锁定当前 Skill 行。
- 同一 Skill 的并发修改通过预期内容摘要或等价的比较条件拒绝陈旧请求。
- 运行结果未知时显示“正在确认状态”，禁止重复提交。
- 对账完成前不更新为成功状态。
- 服务端错误使用稳定代码，不返回 Skill 源码、内部会话标识、凭据或原始异常。
- Registry 与 Agent 状态不一致时停止新的修改操作，并提供只读诊断信息。
- Skill 名称只在未删除记录中保持唯一；已删除记录不会阻止同名 Skill 重新上传。

## 安全边界

移除人工审核不等于移除安全校验。以下能力必须保留：

- ZIP 路径、压缩大小、解压大小、文件数量和单文件大小限制
- 私钥、危险导入、动态代码、子进程、网络、环境变量读取和文件写入扫描
- 允许依赖检查
- 管理员权限检查
- 高风险变更的重新认证和双因素认证
- 不包含敏感内容的审计日志
- 运行制品摘要校验和加载目录隔离

缺少必要依赖或连接配置的 Skill 可以进入库，但必须明确显示“缺少配置”，并禁止启用。

## 删除的旧产品能力

新闭环稳定后删除以下废弃路径，不保留兼容层：

- 人工审核状态、接口、权限、页面和文案
- 候选集合管理页面及公开管理接口
- revision 列表、详情和手动版本选择
- 手动激活、丢弃和回滚交互
- 面向管理员展示的 Registry/Agent 技术状态矩阵
- 仅服务上述交互的前端契约和测试

内部仍被安全切换使用的最小运行机制不因名称相似而盲目删除，应根据真实调用链保留或收缩。

## 验证

至少覆盖以下自动化检查：

- 新 Skill 上传后进入库且默认未启用
- 格式或扫描失败的 ZIP 不进入库
- 同名上传未经确认不能替换
- 陈旧的替换确认不能覆盖新内容
- 替换未启用 Skill 后仍未启用
- 替换已启用 Skill 成功后继续启用新内容
- 替换加载失败时旧内容继续运行
- 启用和停用成功路径
- 启用和停用失败时状态不变
- 删除未启用 Skill
- 删除已启用 Skill 时先停用再删除
- 停用结果未知时禁止删除
- 删除后同名 ZIP 可重新上传为新的未启用 Skill
- Registry 与 Agent 状态一致性
- 权限、重新认证、双因素认证和审计日志负向路径

涉及 Registry 状态和运行切换的验证必须使用真实 PostgreSQL。最终验收必须包含一次真实 AgentOS 端到端流程，不能把因缺少数据库连接而跳过的测试计为通过。

## 实施顺序

### P0：收口人工审核删除

- 清除审核页面、接口、权限、状态和遗留文案。
- 保留自动安全扫描。
- 完成真实 PostgreSQL 回归。

### P1：最小 Skill 生命周期

端到端实现：

`ZIP 上传 → 进入库（未启用）→ 启用 → 停用 → 删除`

### P2：同名 Skill 安全替换

- 冲突响应
- 替换确认弹窗
- 并发保护
- 已启用 Skill 的安全热替换

### P3：删除旧产品层

- 移除候选、版本和技术状态管理交互
- 删除不再使用的接口、契约、权限和测试
- 收缩内部运行机制到产品动作真正需要的范围

### P4：完整验收

- Web、Agent、Skill Registry 和 Skill Core 单元测试
- 类型检查、静态检查和差异检查
- 真实 PostgreSQL 集成测试
- 真实 AgentOS 上传、启用、调用、停用、替换和删除流程

## 后续路线

Skill 生命周期稳定后再依次评估：

1. Skill 调用过程和失败提示。
2. 高风险 Skill 操作的用户确认。
3. 基于真实需求的知识读取能力。
4. 已暂停的长对话上下文管理。

不进入当前范围：多 Agent、人工审核、组织或用户级 Skill 配置、代码仓库导入、Skill 市场和历史版本管理。
