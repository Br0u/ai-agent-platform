# 华鲲官网公开前端覆盖式迁移设计

## 目标

以 `/Users/brou/Downloads/华鲲官网首期低保真原型.html` 为公开官网的信息架构、页面内容和交互来源，将其覆盖迁移到现有 Next.js 官网。迁移后继续使用现站组件、设计变量、响应式策略和动效语言，为后续正式内容替换建立稳定页面结构。

本次不是把原型作为参考，也不是仅调整首页或解决方案样式，而是覆盖原型所包含的全部公开官网前端。

## 核心原则

1. 原型决定公开官网的栏目、页面内容、信息顺序和主要交互。
2. 现有项目决定技术架构、正式路由、组件复用、视觉语言、响应式和可访问性实现。
3. 内容原则上逐字迁移，不擅自润色、删减或补写；仅将原型内部 `data-page` 跳转映射为真实站内路由。
4. 产品、模型、编程、合作伙伴等页面保留其所需的信息密度，不统一套用首页式大留白布局。
5. 未确认数字、案例、下载文件和素材继续明确显示“示意”“待确认”或“待授权”，不得包装成正式对外事实。
6. 不新增依赖；优先复用现有 `SiteShell`、`AppShell`、导航、页面族渲染器、设计变量和测试设施。
7. 不为已经删除的公开页面保留兼容层或回退路由。

## 公开官网迁移范围

### 全局入口

公开顶部导航覆盖为：

- 首页
- 产品
- 解决方案
- 下载中心
- 合作伙伴
- 价格与服务
- 联系我们
- 申请体验

现有 Agent 聊天入口、聊天浮窗和行为保持原样，不重新设计。

登录与文档从公开 Header、Footer 和其他公开导航隐藏，但相关功能和路由保留。

原型顶部评审提示、Logo 下的“官网首期低保真原型”、评审专用 Footer 文案和 `.float` 假聊天占位只属于原型审阅外壳，不迁移。继续使用现站品牌、生产 Header/Footer 外壳和唯一真实 Agent 入口；生产 Footer 的链接只保留迁移后的公开官网栏目。

### 首页与产品体系

迁移原型中的首页、产品总览、独立产品中心，以及全部明确产品页面：

- 码多多 2.0、AIPPT、AISHREK
- 模型中心、模型优化、任务中心、模型资产、模型训练、模型评估、数据准备、模型部署

- 智能体中心、知识智能体、数据智能体、视频智能体、流程编排智能体

- 技能中心及编程类、应用类、办公类技能
- 安全中心

已有正式路由优先原位覆盖；原型包含而当前缺少的正式公开路由按现有命名约定补齐。

### 业务栏目

迁移原型中的：

- 解决方案总览、通用场景、行业方案、实践案例及原型已提供的详情内容
- 下载中心及资源入口

低保真原型内通过脚本生成的页面和详情同样属于迁移来源，不能只检查静态 `<section>` 初始占位。

## 保留且不迁移的系统

以下系统保持现有 UI、路由、数据和行为，不套用原型页面：

- AI 聊天问答及其相关入口
- 登录与注册
- 员工登录、修改密码、双因素认证和敏感操作再认证
- 客户控制台及其子页面
- 运营后台及其子页面
- 文档功能与路由，以及聊天中与文档有关的入口
- 被聊天或控制台直接依赖的支持与帮助路由 `/support`、`/help`

公开 Header、Footer 和其他公开导航不显示登录、文档、支持和帮助入口；从保留系统内部访问这些功能不受影响。

保留系统的页面 UI、数据和关键行为必须以迁移前基线为准，相关实现不得发生非必要改动；验收不仅检查路由可访问，还要锁定其页面壳与关键交互无回归。

## 删除范围

原型未包含、且不属于上述保留系统的现有公开页面应删除路由、页面实现、导航数据和仅由这些页面使用的死代码。当前已知包括：

- Releases 与版本详情
- Roadmap
- OpenLab
- 兼容性
- Marketplace 与资源详情
- 资讯与资讯详情
- 客户案例
- 兜底公开占位页及不再需要的通用公开动态脚手架

删除前必须通过调用关系、内部链接检索，以及文件系统路由与 `routes.ts` 注册表的双向对账，确认目标仅属于删除范围。不能只依赖注册表：未注册但实际存在的公开页面同样必须纳入迁移或删除清单。共享组件若仍被保留系统使用则不得删除。

## 实现结构

采用按页面族覆盖迁移：

1. 全局导航使用现有 `portalNavigation`、`PortalHeader`、`MegaMenu` 和移动抽屉，仅扩展直达栏目与双行动入口。
2. 首页、产品总览、解决方案、下载、合作伙伴、价格、联系和体验保留各自明确页面结构，不强行抽象为一个万能模板。
3. 结构一致的产品中心和产品子页继续使用现有页面族内容模块与共享渲染器；内容模型不足时只增加原型确实需要的最小字段。
4. 原型中的选项卡、目录、步骤切换、筛选和弹层使用现有 React 模式实现，确保键盘操作、焦点管理和移动端可用。
5. 原型素材槽位使用现站风格的明确占位组件，后续可原位替换真实图片，不把素材说明混入正式正文语义。

## 数据与链接规则

- 所有站内跳转使用绝对站内路径。
- 原型 `data-page`、`data-anchor`、详情 key 和筛选条件必须形成明确映射表并由测试锁定。
- 不存在正式内容的按钮不得创造虚假详情页；保留“待确认”状态或引导至已有咨询入口。
- 未确认宣传数字必须和原型的示意提示同时出现。
- 删除公开路由后，迁移范围内不得残留指向这些路由的链接。
- 保留系统直接依赖的公开辅助路由不得删除，只从公开官网入口隐藏。

## 分批交付

1. 全局导航、首页和公开路由基线。
2. 产品总览、独立产品和模型体系。
3. 知识、编程、智能体、行业应用、技能和安全体系。
4. 解决方案及详情。
5. 下载、合作伙伴、价格、联系和申请体验。
6. 删除原型外公开页面、清理死链接并完成全站验收。

每一批都必须先建立失败合同，再实现最小覆盖，最后进行桌面与移动浏览器验收。上一批通过后才进入下一批。

## 验收标准

- 导航栏目、顺序、MegaMenu 内容和行动入口与原型一致。
- 原型中的每个公开页面或脚本生成视图均有真实路由或明确的同页交互承接。
- H1、章节顺序、正文、卡片字段、提示和 CTA 原文与原型一致。
- 首页和高密度产品页面在 1440px、桌面中间宽度和 390px 下无内容折断、横向溢出或错误降密度。
- Agent 聊天入口唯一且行为与迁移前一致；聊天组件代码无变化。
- 登录、注册、员工、控制台、后台、文档、支持和帮助路由仍可访问；页面壳与关键行为基线不变；登录、文档、支持和帮助不出现在任何公开 Header、Footer 或其他公开导航。
- 原型评审提示、评审 Logo 副标题、评审 Footer 和假聊天浮窗均不存在；现站品牌、生产 Footer 和唯一真实 Agent 入口保留。
- 原型外公开路由返回 404，且站内不存在残留入口。
- 页面满足键盘、焦点、语义标题、减少动效和基本对比度要求。
- 目标单测、全量测试、typecheck、lint、format、production build 和全站 Playwright 均通过。
